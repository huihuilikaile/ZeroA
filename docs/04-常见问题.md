# 04 · 常见问题与踩坑记录

这份文档记录本 Demo 开发与实测过程中真实遇到的问题，
每个问题都写清楚：**现象 → 原因 → 怎么判断 → 怎么解决**。

---

## 1. 为什么这里不用 WebSocket？

**现象**：网上很多“子进程 + 前端”的方案都是 `前端 ↔ WebSocket ↔ 后端 ↔ 子进程`。

**原因**：WebSocket 解决的是“浏览器和远端服务器之间的双向通信”。
而 Wails 桌面程序里，前端和 Go 就在同一个进程里，本来就有两条现成的通道：

| 方向 | Wails 机制 | 用途 |
| --- | --- | --- |
| 前端 → Go | Service Binding（`Call.ByID`） | 主动调用，如 `Prompt`、`Abort` |
| Go → 前端 | Event（`app.Event.Emit` / `Events.On`） | 主动通知，如流式文字、状态变化 |

**结论**：再加一层 WebSocket 只会多出端口、鉴权、连接管理、断线重连四个问题，
却没有任何收益。**用平台已经提供的 IPC 就是最短路径。**

> 反过来，如果目标是浏览器里访问远端 Pi，那 WebSocket 就是对的 —— 取决于部署形态。

---

## 2. 界面一直显示「正在生成」，停不下来

**可能原因**（按概率排序）：

1. **把 `agent_end` 当成了结束信号。** 它可能带 `willRetry=true` 再来一轮；
   真正的结束是 `agent_settled`。看 `App.tsx` 里的这两行：

   ```tsx
   if (record.type === 'agent_start') { setRunning(true); setError(''); }
   if (record.type === 'agent_settled') setRunning(false);
   ```

2. **`prompt` 被扩展直接处理了。** 这时 `response.data.disposition == "handled"`，
   **根本不会启动 agent**，也就永远等不到 `agent_settled`。
   `cmd/rpc-demo/main.go` 专门为这种情况写了提前返回。
   本 Demo 用 `--no-extensions` 避开了它，但真实环境会遇到。

3. **事件流断了但界面不知道。** 检查右侧观察器里最后一条记录是什么：
   如果进程已经退出，应该有一条 `process_exit` 的 system 记录，
   界面会据此把状态清空。

---

## 3. 提示「Pi 已启动，请先关闭」

**现象**：点「启动 Pi」失败，但界面上看起来明明没连接。

**原因**：Go 侧的 `PiService.client` 还持有一个**活着的**进程句柄
（例如界面状态因为某种原因没同步，或者上一次关闭没走完）。

**现状**：界面上的「启动 Pi」内部先 `await bridge.Stop()` 再 `Start()`，
所以点一次就能恢复；实在不行点「关闭进程」。

**更根本的教训**：`Start` 与 `Stop` 必须成对可重入 ——
“界面显示未连接”和“后端真的没有进程”是两件事，不能互相推断。

---

## 4. 响应超时了，但模型还在输出

**原因**：`context` 超时只是**你不再等待**，不会通知对面停止。
两者是完全不同的动作：

| 动作 | 效果 |
| --- | --- |
| `ctx` 超时 | 本地放弃等待；请求在 `pending` 表里被清理 |
| `abort` 命令 | 让 Pi 停止当前回合 |
| `Close()` | 关掉整个进程 |

**正确做法**：超时后如果确实不想让它继续，补一条 `abort`
（`cmd/rpc-demo/main.go` 的超时分支就是这么写的）。

---

## 5. 改了 `PiService` 的方法，界面点按钮才报错

**原因**：Wails 是按**数字方法 ID** 调用的。绑定文件
（`frontend/bindings/zeroa/piservice.ts`）里写死了 ID，
改了 Go 方法名而没重新生成绑定，编译和类型检查都不会报错。

**解决**：重新运行构建脚本（会重新生成绑定）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1
```

**提前发现**：`go test ./...` 里的 `TestGeneratedBindingsMatchService`
会对比绑定导出的方法与 `PiService` 的方法名，直接报错提示你重新生成。

## 6. 新克隆的仓库 `go build ./...` 失败

**报错**：

```text
main.go:17:12: pattern all:frontend/dist: no matching files found
```

**原因**：`//go:embed all:frontend/dist` 在**编译期**读取目录，
而 `frontend/dist/` 是构建产物、不提交。

**解决**：先跑一次构建脚本（它会先建目录、生成绑定、再打包前端）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1
```

**注意**：`go test ./internal/...` 和 `go run ./cmd/rpc-demo` 不依赖它，随时可跑。

---

## 7. 桌面程序启动时闪出一个黑色控制台窗口

**原因**：Go 默认编译成 Console 子系统（PE Subsystem=3），
启动时会附带一个控制台窗口。

**解决**：构建时加链接参数（`scripts/build.ps1` 已经加上）：

```powershell
go build -ldflags '-H windowsgui' -o bin/zeroa.exe .
```

**验证方法**：

```powershell
$bytes = [System.IO.File]::ReadAllBytes('bin\zeroa.exe')
$pe = [BitConverter]::ToInt32($bytes, 0x3C)
[BitConverter]::ToUInt16($bytes, $pe + 0x5C)   # 2 = GUI，3 = Console
```

## 8. 真实模式找不到 `pi`

**查找顺序**（见 `internal/pi/command.go`）：

1. 界面上填写的「Pi 路径」；
2. 环境变量 `PI_CLI_PATH`；
3. PATH 里的 `pi`。

**Windows 特别注意**：npm 安装出来的入口是 `pi.cmd`（批处理包装）。
直接执行它会多一层 `cmd.exe`，路径带空格时还要处理引号。
本 Demo 的做法是读 npm 全局目录下
`node_modules/@earendil-works/pi-coding-agent/package.json` 的 `bin` 字段，
拿到真正的 `cli.js`，改成直接启动 `node cli.js`
（本机实测该字段是 `dist/bundle/cli.js`）。

**排查**：在终端里跑 `pi --version`，再跑 `go run ./cmd/rpc-demo -mode real -check`
（不会调用模型，不花钱）。

## 9. 收到的中文/特殊字符会乱码吗？

不会，前提是三条都成立：

- **传输**：JSONL 是 UTF-8，Go 的 `json.Marshal` 会转义控制字符但保留中文；
- **分帧**：按字节找 `LF`，不按字符数 —— Go 的 `bufio.Scanner` 就是这么做的；
- **显示**：终端/WebView 要按 UTF-8 解码。Windows 老控制台建议
  `chcp 65001` 或直接用 Windows Terminal。

一个容易忽略的坑：Unicode 的 **U+2028 / U+2029** 在某些语言里会被当成换行。
本 Demo 的分帧只认 `LF`，所以它们能安全待在 JSON 字符串里 ——
测试 `TestLargeUnicodeRecord` 就是在验证这件事。

## 10. 一条消息太大会怎样？

本 Demo 的边界（都写在 README 的“约束”里）：

| 限制 | 位置 | 超限行为 |
| --- | --- | --- |
| 单条消息 32 KB | `service.go` 的 `Prompt()` | 直接报错，不发送 |
| 单条入站记录约 4 MiB | `client.go` 的 `scanner.Buffer` | 丢弃该行并结束进程（stdout）；stderr 只记录不结束进程 |

**为什么要有上限**：没有上限的解析器等于内存炸弹。
设置上限就要明确“超限之后怎么办”，而不是让它悄悄出错。

## 11. 想换成 Vue / Svelte / Electron / 终端界面

**好消息**：`internal/pi` 不知道界面的存在，一行都不用改。

需要替换的只有外层：

```text
main.go + service.go + frontend/     ← 换成别的壳
        ↑
        │  这里只依赖 internal/pi 的公开方法：
        │  pi.Command / pi.Start / Client.Request / Client.Close / Trace 回调
```

- 换 Vue/Svelte：只改 `frontend/`，绑定仍是同一份（Wails 支持这三个模板）；
- 换 Electron：把 `internal/pi` 的逻辑用 Node/TypeScript 重写，或把 Go 程序编译成 sidecar；
- 换终端界面：直接参考 `cmd/rpc-demo/main.go`，它已经是一个完整的 TUI 雏形。

**判断标准**：如果替换界面时需要改 `internal/pi`，说明分层被破坏了。

## 12. 能同时跑多个 Pi 进程吗？

当前设计是**一个 `Client` 对应一个进程**，`PiService` 也只持有单个 `client`。

要扩展成多 Agent，改动点在**事件信封**上：给每条事件加上 `agentId`，
前端按 `agentId` 分桶即可，路由逻辑不用重写：

```jsonc
// 现在
{"type":"text_delta", ...}
// 多 Agent 之后
{"agentId":"agent-a","event":{"type":"text_delta", ...}}
```

这也是为什么代码里把“协议层”和“界面层”分得比较干净 ——
扩展时改动集中在一个地方。

## 13. 这个 Demo 明确不做什么

避免误解，列清楚边界：

- **不管理会话**：用 `--no-session`，每次都是临时对话，没有历史与恢复；
- **不加载扩展**：用 `--no-extensions`，所以 `web_search` 这类扩展工具不可用
  （内置文件/命令工具是开着的，见下一节）；
- **不做进程树清理**：只关直接子进程，不追杀它启动的孙进程
  （真实产品在 Windows 上需要用 Job Object）；
- **不做安全沙箱**：`cwd` 不是权限边界，子进程仍以当前用户身份运行；
- **不是 RPC SDK**：只实现了 `get_state` / `prompt` / `abort` 三条命令。

需要这些能力时，正确做法是在 `internal/pi` 上继续加，而不是把逻辑塞进界面。

## 14. 为什么 Pi 说“我没有文件写入/命令执行工具”？

因为**启动参数**决定了它手里有哪些工具：

```go
// internal/pi/command.go（当前版本）
args := []string{"--mode", "rpc", "--no-session", "--no-extensions", ...}
```

Pi 的默认工具是 `read` / `bash` / `edit` / `write`（默认启用），
另有 `find` / `grep` / `ls` / `powershell` 可按需开启。
如果参数里出现 `--no-tools`，**内置、扩展、自定义工具会被全部禁用**，
此时模型看到的工具表就是空的，它只能回答“我没有工具”。

判断方法与改法：

| 想达到的效果 | 参数 |
| --- | --- |
| 全部内置工具（能写文件、能执行命令） | 不加任何工具开关（当前默认） |
| 只读写文件，不给命令执行 | `"--tools", "read,write,edit"` |
| 只读 | `"--tools", "read"` |
| 完全禁用 | `"--no-tools"` |

改完必须重新运行 `scripts/build.ps1` 重新编译——参数是编译进 Go 二进制的。

**安全提醒**：`bash` = 以你的用户身份执行任意命令，`write`/`edit` = 直接改磁盘文件。
界面上如果要放开这些能力，理想做法是给每一步工具调用加确认
（Pi 的 RPC 为此提供了 `extension_ui_request`，见 `docs/rpc-extension-ui.md`）。

## 15. 遇到问题时最快的定位路径

```text
① 看右侧观察器最后几行原始记录
     ├─ 有 stdin 没有 stdout        → Pi 没回：卡住？崩了？参数不对？
     ├─ 有 response.success=false   → 命令本身被拒绝，看 error 字段
     ├─ 有事件但界面没变化          → 前端分支问题（App.tsx 的 if 判断）
     └─ 有 stdout_read_error        → 记录超限或分片异常
② 想确认“到底连没连上”：点「查询状态」，看能否拿到同 id 的 response
③ 想确认“进程还活着吗”：看有没有 process_exit 记录
④ 想复现但不花钱：用 mock 模式，大多数问题在 mock 下同样能复现
```

**记住一句话**：原始 JSONL 永远是真相，界面只是它的一种呈现。
调试时先看原始记录，不要先猜界面。
