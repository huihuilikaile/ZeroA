# 08 · 子智能体形态（照 DSH 抄什么、不抄什么）

这份文档记录一次**有依据的仿制**：读了 DeepSeek Harness（DSH）的子智能体实现之后，
把它值得抄的东西落到本项目，同时写清楚**哪些刻意不抄、为什么**。

DSH 的源码来自桌面版 `app.asar` 里抽取的插件包（`dsh-subagent`、`dsh-subagent-*-in-process`、
`dsh-tool-subagent*`、`dsh-client-ui-subagent`、`dsh-experimental-agent-team*`），
关键结论都有 `文件:行` 出处；本文只保留结论与取舍。

---

## 0. 一句话

```text
DSH 的子智能体不是"一次性任务"，而是"可以一直说话的同事"：
跑完一轮它不消失，只是**空闲**；你能继续给它派活，也能只掐掉它当前那一轮。
我们照这个改了形态与状态语义，但保留了"一个子智能体 = 一个独立 Pi 进程"这个差异。
```

---

## 1. 改之前 vs DSH

| 维度 | 我们（改前） | DSH | 改后（本轮） |
|---|---|---|---|
| 一轮结束后 | **结算 + 关进程**，之后只读 | 进程/Actor 仍在，状态 `idle` | 可继续形态**驻留**；一次性形态保持原样 |
| 状态语义 | `completed` 一个枚举同时表达"跑完了"和"结束了" | 活动态（running/inactive）与结果（`lastTurnCompleted` 布尔）**分开** | `idle` + `LastTurnCompleted` 两个字段 |
| 能不能追问 | 不能 | `send_message`：工作中 Steer、空闲开新轮 | `SendToAgent`（steer / queue） |
| 停一个子智能体 | 只有 Kill（销毁） | `interrupt_agent` 只停当前轮；销毁是另一回事 | `InterruptAgent`（不销毁）+ 原有 `KillAgent` |
| 容量 | `MaxParallel=2` | `maxActiveSubagents=8`，**超限直接拒绝不排队** | 新增 `MaxContinuable=8`，同样拒绝不排队 |
| 父级何时拿到结论 | 只在子智能体结束时 | 每轮结束一条 settlement notice | 新增 `TurnSink`：**每一轮**都回传阶段成果 |

## 2. 抄了哪 6 条（按性价比）

### 2.1 形态分裂：`one-shot` / `continuable`

DSH 把子智能体分两种形态：一次性（跑一次、一个结果、所有权转移）与可继续（持久会话、
按顺序接受后续消息、同时最多一个进程内 Activation）。工具行的 `backgroundMode` 选择形态。

我们对应实现：`agents.Mode` + `SpawnRequest.Mode`，默认 **continuable**（角色里写
`delegation.lifecycle: one-shot` 可退回老行为）。

**为什么值得抄**：这是"能不能追问"的分水岭。一次性形态下，用户想补一句"顺便看看 XX"
只能重新派一个子智能体——那意味着**重新起进程、重新加载上下文、重新解释一遍任务**。

### 2.2 状态与结果分开：`idle` + `LastTurnCompleted`

DSH 里没有 status 枚举，运行态是现算的 `running|inactive`，而"最近一轮是否正常完成"是
一个单独的布尔 `subagentTiming.lastTurnCompleted`；UI 用它决定绿点/灰点。

我们对应实现：`Status` 新增 `idle`，`Instance` 新增 `LastTurnCompleted` 与 `Turns`，
`TurnSettled()` 与 `Status.Finished()` 是两个不同的问题。

**为什么值得抄**：把两者混在一个枚举里，必然出现"失败被显示成完成"或"跑完了却显示还在忙"。
我们实现时也真的踩到了：中断那一轮的 `stopReason` 读错了层级（见 §4），
如果没有这个布尔，界面会把"被中断"显示成绿点"完成"。

### 2.3 投递方式按**发送者**分工：模型 Steer、人 Queue

DSH：模型写的消息固定走 Steer（赶最近的 step 边界），浏览器里人类输入的 prompt
可以在 Queue / Steer 之间选；落到底层是 `agent.steer()` vs `agent.followup()`。

我们对应实现：`SendToAgent(agentId, message, delivery)`；扩展里的 `send_to_agent`
默认 `steer`，界面里的输入框默认 `queue`（不打断它手上的工作）。

**为什么值得抄**：这不是实现细节，而是**语义**——"别停，把这点也考虑进去"与
"等你忙完再说"是两种不同的意图，用同一个接口表达会一直别扭。

### 2.4 `interrupt` 与 `kill` 分开

DSH 的 `interrupt_agent`：只停当前轮次，队列与下属都保留，调用立即返回不等待，
对已结束的目标是**空操作但受理**。销毁是另一条路径。

我们对应实现：`Supervisor.Interrupt`（发 `abort`，不关进程）与 `Kill`（取消 + 释放）。

**为什么值得抄**：可继续形态下，"停下来"和"结束它"是两件事。只有 kill 的话，
用户想纠正方向就只能杀掉一个已经有上下文的子智能体。

### 2.5 容量：满了**直接拒绝**，不排队

DSH 的 `ActivationPool.reserve()`：超限抛 `ACTIVATION_LIMIT_REACHED`，**不排队**——
理由写得很清楚：占着名额的可能正是"派了活正在等结果"的父级，排队会让它自己等自己。

我们对应实现：`Options.MaxContinuable`（默认 8）+ `ErrTooManyContinuable`；
空闲驻留只占这个名额，不占 `MaxParallel`（同时在跑的回合数）。

**为什么值得抄**：这是"看起来更友好、实际会死锁"的典型反例。

### 2.6 每一轮都回传阶段成果

DSH 在驻留 Activation 结算时，会在父级自己的轮次流里告知该子级的结果（settlement notice）。

我们对应实现：`Supervisor.SetTurnSink`，在 `markIdle`（一轮正常结束时）回调，
经既有的 `Router` 投递回父会话；并且在终结时**不重复投**已经投过的那一轮
（否则父会话里会出现两条一模一样的"子智能体结果"）。

**为什么值得抄**：一个驻留 10 分钟、跑了好几轮的子智能体，如果只在被回收时通知父级，
父级在整个过程中都以为它还没出结果。

## 3. 刻意**不**抄的（含理由）

| DSH 的做法 | 为什么不抄 |
|---|---|
| 三个驱动都**同进程**（in-process spawn / fork） | 我们每个子智能体是独立 Pi 进程：权限交集、预算、单独 kill、崩溃隔离都靠它。DSH 的 fork 只是"复制一份事件数组当 seed"，也不涉及进程 |
| 状态靠"父会话 catalog fact + 子会话 descriptor"**持久化并重放** | 那要动会话文件格式与投影层（`subagentCatalog` projection、`stateVersion` 重折）。我们的登记表在内存里，切会话即清空——**这是已知短板，见 §6** |
| `agent-team` 的**任务板**（`blockedBy` DAG + `expectedRevision` CAS） | 值得抄，但它是独立功能（9 个工具 + 广播 + 持久化），不该混进这一轮。我们的委派是"父派一次活"，还没有"共享任务队列"的需求 |
| `wait_agent` 那种"只观察不唤醒" | 我们有 `Wait`/`WaitTurn`，语义已经够用；DSH 的 wait 只在 agent-team 里 |
| UI 的"头部面包屑 + 下拉树 + 右侧分栏" | 我们的 `AgentTabs` 是横向标签栏，切换本来就不重建视图；重做导航层收益小、风险大。**抄的是状态语义与计数徽标**，不是布局 |
| 进度百分比 | DSH 明确没有（locale 表里没有对应 key）。没人知道还剩几步，假进度比没有更糟 |

### 4.1 一个只有跑起来才会发现的缺口

加完工具后跑了一次真实启动，日志里出现：

```text
pi_default_tools_updated ... added=delegate_task,delegation_list,delegation_stop,catalog_list,...
```

**两个新工具不在那张表里**。Pi 的扩展工具默认是 inactive，要靠 `settings.json` 的
`defaultTools` 显式启用（`+name` 形式）——不补上，模型就"看不到"`send_to_agent`，
功能写了也用不上。这个坑项目里踩过一次（见 `pi_settings.go` 顶部的注释），
这次是因为"新工具"没有同时改三处：**扩展注册 + defaultTools 表 + 角色工具白名单**。
三处都补上之后才算真的接通。


**另一处实现坑（值得记）**：`WaitTurn` 的唤醒通道曾经在 `beginTurn` 里被重置成 nil，
于是"等这一轮结束"的等待者永远收不到通知——它会一直等到空闲回收（5 分钟）才返回，
表现为"结论明明出来了，界面要等好久"。回归用例：
`TestContinuableStaysIdleAndAcceptsFollowUp`（修复前会红）。

## 6. 还没做的（下一步可选项）

1. **冷恢复**：DSH 的持久子会话可以"冷恢复"（直接 child 无 Activation 时从会话文件重建）。
   我们的子智能体 `SessionDir` 已保留，但进程一释放就不能再说话。
   做法：再次发消息时新起一个进程 + `switch_session` 到它上次的会话文件，上下文即可恢复。
2. **登记表持久化**：现在切会话/切工作区会 `clear()` 掉 Agents 登记表，历史子智能体在界面上消失。
   DSH 的做法是把 `subagent/catalog` 事实写进**父会话日志**，读时重放。
   我们可以照抄到 `gui-state.json`（比改会话文件格式安全），或者写进会话文件的一个自定义记录。
3. **任务板**（agent-team 那层）：`blockedBy` DAG + `expectedRevision` CAS + 写域重叠告警。
   只有在"多个子智能体共享一份任务队列"的真实需求出现时才做。
