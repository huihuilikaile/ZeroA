## 1. 没有沙箱：它真的会动你的机器

本工具**不提供任何隔离**。模型决定执行的命令，是在**你的操作系统上、以你的用户权限**运行的：

- `bash` 工具就是本机 shell：能读写、能删除、能改权限、能起进程、能联网、能装东西。**它没有目录边界，也没有命令白名单**（除非你自己在角色/权限里收紧）。
- 文件工具（`read` / `write` / `edit`）能改**你有权限改的任何文件**，不只是工作区。
- **子智能体**是额外的独立进程，同样以你的权限执行命令——也就是说，"我派它去查个资料"背后可能是好几个进程同时在动你的机器。
- **MCP 服务器是第三方程序**（例如 IDA / Burp / jadx 的 MCP 扩展）：它们能真的发包、真的改工程文件、真的驱动你的商业软件。它们的行为、稳定性与合规性由各自作者负责，本工具只是连接它们。
- 权限系统是**工具级**的（允许 / 询问 / 拒绝），**不是参数级**的：它能拦住"用不用 bash"，拦不住"用 bash 干了什么"。

**必须由你承担的典型风险**：文件被覆盖或删除、代码仓库被改乱、系统配置被修改、数据库被写坏、被扫描/被攻击的第三方服务、你的 IP 被目标封禁或追溯、产生真实的网络流量与费用。

**强烈建议**：先在**虚拟机 / 快照可回滚的环境**里跑；重要数据先备份；不要把生产环境的凭据、密钥、客户数据交给它；对每个破坏性命令，**自己看一眼再同意**。

## 2. AI 幻觉：它会自信地说错，而且代价可能是真的

大语言模型会**编造**，而且编得很像真的：

- 编造命令、参数、API、库函数（"这个函数在 3.x 里存在"——其实不存在）；
- 编造**执行结果**：声称"我跑过了，输出是 X"，而实际没跑或跑失败了；
- 编造**结论**：把猜测当事实，把"看起来像 flag"的字符串当成 flag 交付；
- 编造**引用**：给出不存在的 URL、不存在的 CVE、不存在的 writeup；
- 在长上下文里**忘记**你前面说过的约束，然后继续按自己的理解执行。

本工具做了这些缓解，但它们**都不能消除幻觉**：提示词要求"实测优先/失败留痕/交叉验证"、子智能体的结论只是候选（父需复核）、工具卡片展示真实输出、环境清单是"线索不是保证"。

**AI 的错误 + 没有沙箱 = 真实的破坏力**：一条被幻觉出来的 `rm` 路径、一次"我以为在靶场"的扫描、一个抄错的参数，都可能造成不可逆的后果。

**使用者的义务**：把 AI 的输出当成**候选答案**，而不是结论；对关键结论自己复现；对破坏性/对外可见的操作，先确认影响面。
