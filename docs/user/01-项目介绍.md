# ZeroA · 项目介绍

> 一个把 [Pi coding agent](https://github.com/badlogic/pi-mono) 装进 Windows 桌面的工作台。
> 角色是一等公民，工具可插拔（内置 / 扩展 / MCP），复杂任务可以派子智能体并行做。

> ⚠️ **先读 [免责须知](00-免责须知.md)**：本工具**没有沙箱**，AI 会以你的权限真实执行命令、联网、改文件，而且会幻觉。
> **适用**：已授权的 CTF 比赛、靶场、自有资产的安全研究。
> **不要**：把模型密钥、许可证、比赛附件、Flag 或工作区数据提交到公开仓库；也不要用在未授权的目标上。

---

## 1. 它解决什么问题

直接对着命令行里的 AI 助手解题，会遇到三个反复出现的麻烦：

| 麻烦 | ZeroA 的做法 |
|---|---|
| 每次都要重新交代"我是谁、我用什么工具、我按什么流程做" | **角色**：提示词、工具白名单、技能、权限、模型、自动压缩、任务循环一次性配好，切换角色 = 换一套工作方式 |
| 长任务上下文爆炸，或者一个方向卡死就全卡死 | **子智能体**：父 Agent 可以把"查资料 / 复核结论 / 试另一条路线"派给独立进程，各自独立上下文，结论摘要回传 |
| 本机工具（IDA / Burp / jadx / 各种脚本）和模型是两套世界 | **MCP + 主机工具检测**：把本机工具接成模型能直接调用的工具；"工具"页负责检测本机有什么 |

再加上工程上必要的那些：会话落盘、工作区隔离、四层权限、用量与上下文占用、停止与恢复。

## 2. 它是怎么搭起来的

```
┌──────────────────────────── ZeroA（Wails v3 桌面应用，Go + React/TS）────────────────────────────┐
│                                                                                                │
│  界面（React）                           Agent Host（Go）                    Pi 进程（Node）    │
│  ├ 对话 / 时间线 / 工具卡片              ├ 启动与停止 Pi          stdin/stdout  ├ 真实会话        │
│  ├ 角色 · 工具 · 权限 三个页面      ⇄    ├ 事件解析与路由（JSONL RPC）  ⇄       ├ 工具执行        │
│  ├ 会话 / 工作区 / 文件面板              ├ 角色编译（提示词·工具·权限）        ├ 扩展 / 技能     │
│  └ 子智能体标签页                        ├ 子智能体登记与投递                  └ MCP 客户端      │
│                                          └ 委派桥（127.0.0.1 随机端口 + 会话令牌）              │
└────────────────────────────────────────────────────────────────────────────────────────────────┘
```

三条设计原则，读文档时会有用：

1. **Go 是进程的主人**：谁启谁停、能派几个子智能体、结果什么时候回传，都在 Go 里做判定——模型只是"请求"，不是"决定"。
2. **模型看到的一切都可追溯**：提示词分段、工具清单、环境清单都落成文件（`bin/.pi/roles/prompts/*.md`），可以逐字核对"它到底被告知了什么"。
3. **不可靠的地方明说**：工具清单是线索不是保证、子智能体结论是候选不是事实——提示词里都写着，界面上也留证据（工具卡片、原始事件、会话文件）。

## 3. 能力清单（都已实机验证）

**对话与工程**
- 真实 Pi 会话：流式回答、思考折叠、工具卡片（命令 + 输出 + 退出码 + 耗时）
- 会话落盘到 `<数据目录>/sessions/`，左栏按工作区分组；新建 / 切换 / 重命名 / 删除
- 工作区 = Pi 的工作目录；文件面板带边界检查；输入框支持**拖拽**与**粘贴**上传文件
- 上下文占用环、累计 token、每回合耗时、速率（tok/s）

**角色系统**
- 每个角色一套：提示词 / 工具白名单 / 技能 / 权限 / 模型与思考级别 / 自动压缩 / 任务循环 / 委派配置
- 角色可切换（切换 = 重启 Pi + 新会话，因为提示词与工具集只能在启动时确定）
- 会话记得自己属于哪个角色；重启应用后"这个会话当时用的什么角色"仍然可见

**工具**
- 四条来源：Pi 内置工具、**扩展**（TypeScript 插件）、**MCP 服务器**、**技能**（按需加载的 md 知识）
- MCP 支持 stdio 与 streamable HTTP；本机三口实测：IDA Pro（66 工具）、jadx（32 工具）、Burp Suite（27 工具）
- "工具"页检测本机环境工具（可用 / 缺失 / 重新检测）；给模型看的**环境清单**按角色声明的能力生成——勾选了的才给，没勾选的不给

**权限与安全**
- 四层策略交集（全局 → 角色 → 会话 → 临时授权），三种结果：允许 / 询问 / 拒绝
- 临时授权有面额（15 分钟 ~ 4 小时），到期自动收回
- 权限页能看到"最终生效的权限"和它是怎么算出来的

**子智能体（并行助手）**
- 父 Agent 用 `delegate_task` 派活，**立刻返回**，父继续干活
- 每个子智能体是独立进程、独立上下文、独立会话文件；顶部标签页可切过去**只读查看**它自己的会话
- 结论以摘要形式回到父会话，父负责交叉验证（提示词明确要求"不要只是复述"）
- 自动收口：父会话结束/中止/结果无人接收、角色关掉委派、主 Agent 给出候选 flag —— 都会停掉还在跑的子智能体

**任务循环**
- 一轮结束后要不要继续：轮次上限、时长上限、卡住计数、到限行为（停 / 先总结再停）
- 留空 = 完全由你驱动（默认：什么都不做）

## 4. 需要什么

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11（x64） |
| **Node.js** | **≥ 22.19.0**（Pi 运行时要求；`node --version` 能查到即可） |
| 模型 | 任一 OpenAI 兼容或 Pi 内置提供商（DeepSeek / Kimi / OpenAI / Anthropic…）；在"设置 → 模型"里填 API 密钥 |
| 可选工具 | IDA / jadx / Burp / Python / pwntools / frida… 装了就在"工具"页显示为可用，没装不影响主流程 |

> 便携包**不含** Node，也不含 IDA/Burp/jadx 本体——它们各自有许可证，请自行安装。

## 5. 目录结构

```
ZeroA/
├─ zeroa.exe          桌面应用（双击运行）
├─ rpc-demo.exe            命令行演示（不启动界面，看协议用）
├─ pi-agent/               Pi 运行时（node_modules，不含 node 本体）
├─ workspace/              默认工作区（模型读写的目录）
├─ tools/                  随包附带的小工具（如 jadx 的 MCP 服务端）
└─ .pi/                    数据目录：所有配置与会话都在这里
   ├─ settings.json        默认模型 / 提供商 / 思考级别 / 主题 / 资源开关
   ├─ auth.json            API 密钥（用户自己填的）
   ├─ models.json          自定义模型定义
   ├─ mcp.json             MCP 服务器列表
   ├─ roles/               角色定义 + 生成出来的提示词分段
   │   ├─ <角色>.json
   │   └─ prompts/<角色>.md         角色提示词
   │       prompts/<角色>.env.md    环境清单（每次启动按实测重写）
   │       prompts/<角色>.delegation.md  委派说明（按角色委派配置生成）
   ├─ skills/              技能（md，按方向分目录）
   ├─ extensions/          扩展（TypeScript 插件）
   ├─ sessions/            会话文件（Pi 的 JSONL 会话，按工作区分目录）
   └─ agents/<id>/sessions/  子智能体的会话文件
```

**备份 / 迁移**：整个 `.pi/` 目录就是全部状态。换机器时把 `ZeroA/` 整个拷过去即可（密钥也在里面，注意别外传）。

## 6. 第一次运行（约 2 分钟）

1. 解压到任意目录（路径避免中文与空格更稳），双击 `zeroa.exe`。
2. 打开 **设置 → 模型**：选一个提供商，填入 API 密钥，保存。
   （密钥写入 `.pi/auth.json`；界面不显示明文，只看"已配置密钥"标记。）
3. 左栏「工作区」里点 **＋** 新建一个会话；输入框左下角选一个角色（例如「CTF 竞赛」）。
4. 输入第一条任务消息，回车发送。
5. 想看它到底调用什么工具：对话里的**工具卡片**直接展开；还有原始事件的观察器。

## 7. 已知边界（诚实清单）

这些不是 bug，是当前版本的取舍，写出来免得你踩：

- **工具集在会话启动时确定**：改了角色的工具白名单、装了新扩展，都要**新建会话**才生效（Pi 的限制，界面会提示）。
- **权限是工具级的**：能表达"允许 bash"，还不能表达"只允许这几条命令"或"读写限制在工作区内"。默认情况下 bash 跟随角色配置（CTF 角色就是本机全权限，请只在授权环境用）。
- **扩展要手写 TypeScript**：界面能管理技能与 MCP，但"写一个新扩展"仍需自己写 `.ts` 放进 `extensions/`（仓库里有示例）。
- **子智能体回传的是摘要**：默认 8 KB 上限，完整过程留在该子智能体的会话文件里（界面上有路径）。
- **环境清单是线索不是保证**：清单来自本机检测，写命令前让模型自己 `command -v` 确认一遍（提示词里已要求）。
- **子智能体的对话框不能应答**：它请求交互时只能在它自己的时间线里看到，人类无法从界面回答（界面会明说"本视图暂不能应答"）。
