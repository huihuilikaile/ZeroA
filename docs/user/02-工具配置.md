# ZeroA · 工具配置

这篇讲"怎么把工具配到能用的状态"。分三层：**全局**（设置）、**角色**（一套工作方式）、**会话**（当场决定，只有几项）。

界面上对应的入口：`角色` 页（绝大部分配置在这里）、`工具` 页（本机环境工具检测）、`权限` 页（权限与临时授权）、`设置`（模型 / 密钥 / 资源开关）。

---

## 1. 模型与密钥

**设置 → 模型**

| 操作 | 说明 |
|---|---|
| 选提供商 + 填 API 密钥 → 保存 | 密钥写进 `bin/.pi/auth.json`；Pi 的"登录"就是这个动作 |
| 自定义模型 | 改 `bin/.pi/models.json`（提供商、模型 id、baseUrl、上下文窗口、是否支持推理） |
| 切换模型 / 思考级别 | 输入框右下角的下拉（角色也可以锁定"只能用这几个模型"） |

要点：
- **密钥改动要重启会话**（新建会话即可）。界面会提示"重启会话后生效"。
- 角色里可以写 `模型` 与 `思考级别`，切换角色时会核对"实际生效的模型"和声明是否一致，不一致会明说。
- 缺密钥的典型报错：`No API key found for provider …` —— 回到设置页补密钥。

## 2. 角色：一套可复用的工作方式

`角色` 页左侧是角色列表，右侧是这个角色的全部配置。**切换角色 = 重启 Pi + 新会话**（提示词与工具集只能在启动时确定）。

| 配置块 | 作用 | 备注 |
|---|---|---|
| 身份 | 名称、图标、描述、角色前缀 | 前缀用于新会话命名（如 `[CTF] …`） |
| 模型与思考级别 | 这个角色用什么模型、思考多深 | 可限制"只允许这几个模型" |
| 会话 | 会话目录、是否继承上个会话 | 一般不用改 |
| 角色提示词 | 这个角色的行为准则（**可编辑**） | 落盘为 `roles/prompts/<角色>.md`，可逐字核对 |
| 导入 / 导出 | 把角色带走或分享 | **设置 → 角色 → 角色导入 / 导出**：导出成一个自包含 JSON（含提示词），导入支持该 JSON 或目录形式（`*.json` + `prompts/<id>.md`）；同名覆盖 |
| Pi 工具 | 工具白名单 / 黑名单 | 见下一节 |
| 方向工具线索 | 写进提示词的"本机哪些工具可用" | 与"工具"页的检测结果互补 |
| 技能 | 勾选启用（按方向分组） | 技能本体是 `skills/` 下的 md，可导入目录 |
| 权限（角色层） | 这个角色申请哪些工具权限 | 与其它三层求交集 |
| 联网能力 | 提示"是否具备联网工具" | 实际工具由扩展/MCP 提供 |
| MCP 服务器 | 增删 / 启停 / 打开配置文件 | 见第 4 节 |
| 自动压缩 | 上下文快满时自动压缩的阈值 | 走 RPC，切换角色即时生效 |
| 任务循环 | 轮次上限 / 时长上限 / 卡住计数 / 到限行为 | 留空 = 什么都不做 |
| 子智能体委派 | 允许派哪些角色、最多几个、要不要先审计 | 见第 6 节 |

### 工具白名单的三种语义（容易搞错）

| 写法 | 含义 |
|---|---|
| `"tools": null` / 不写 | **不限制**：用 Pi 的默认工具集（read / bash / edit / write…） |
| `"tools": []` | **全禁**：一个工具都不给（`--no-tools`） |
| `"tools": ["read","grep","bash"]` | **白名单**：只给这些 |

排除列表 `excludeTools` 是在白名单基础上再减。界面上有「全选 / 全不选 / 不限制」三个按钮。

> ⚠️ 界面上的"Pi 工具"复选框列的是 **Pi 内置工具**。扩展注册的工具（如 `delegate_task`、`web_search`、`ssh`）、MCP 工具（`mcp__<服务器>__<工具>`）**不在这个列表里**——想精确控制它们，编辑 `roles/<角色>.json` 的 `tools` / `excludeTools`。这也是当前版本一个已知的不足。

## 3. 工具的四条来源

| 来源 | 位置 | 怎么加 | 谁控制 |
|---|---|---|---|
| **Pi 内置** | Pi 自带 | 无需安装 | 角色白名单 |
| **扩展** | `<数据目录>/extensions/*.ts` | 自己写 TS 放进目录 | 角色 `extensions` 字段 + 设置里的"加载资源"开关 |
| **MCP 服务器** | `<数据目录>/mcp.json` | 界面增删，或直接改文件 | 角色 `mcpServers` |
| **技能** | `<数据目录>/skills/**/*.md` | 写 md / 导入目录 | 角色勾选 |

### 写一个扩展（最小示例）

```ts
// bin/.pi/extensions/my-tool.ts
import type { ExtensionAPI } from '@earendil-works/pi-coding-agent';

export default function (pi: ExtensionAPI) {
  pi.registerTool({
    name: 'hash_file',                       // 模型看到的工具名
    label: 'Hash file',
    description: '算一个文件的 sha256，用于比对附件是否被改过。',
    parameters: {
      type: 'object',
      properties: { path: { type: 'string', description: '文件绝对路径' } },
      required: ['path'],
    },
    async execute(_id, params: { path: string }) {
      const { createHash } = await import('node:crypto');
      const { readFile } = await import('node:fs/promises');
      const digest = createHash('sha256').update(await readFile(params.path)).digest('hex');
      return { content: [{ type: 'text', text: digest }], details: {} };
    },
  });
}
```

放好后**新建会话**，模型的工具清单里就会出现 `hash_file`（第一步先问它"你有哪些工具"验证）。

### 技能（md）

```
bin/.pi/skills/<技能名>/SKILL.md       ← 正文（自建或导入的技能包，建议按方向命名目录）
bin/.pi/skills/<技能名>/references/*.md ← 可选的参考材料，模型按需再读
```

技能是"按需加载的知识"，不是工具：模型在需要时读它（例如"RSA 常见攻击清单"）。角色里勾选启用；界面上有「打开技能目录 / 重新扫描 / 导入目录」。

## 4. MCP 服务器

### 配置格式（`bin/.pi/mcp.json`）

```jsonc
{
  "mcpServers": {
    "ida": {
      "url": "http://127.0.0.1:13391/mcp",     // streamable HTTP
      "description": "IDA Pro（可选，界面用）"
    },
    "jadx": {
      "command": "C:\\path\\to\\python.exe",   // stdio
      "args": ["C:\\path\\to\\jadx_mcp_server.py", "--jadx-port", "8650"],
      "env": { "SOME_VAR": "value" }
    },
    "burp": {
      "command": "java",
      "args": ["-jar", "C:\\path\\to\\mcp-proxy-all.jar", "--sse-url", "http://127.0.0.1:9876"]
    }
  }
}
```

- **只支持 stdio 与 streamable HTTP**。旧式 SSE（`/sse` 那种）会被拒绝——需要桥接：用服务端自带的 stdio 代理（如 Burp 官方扩展的 `mcp-proxy-all.jar`）或 `mcp-proxy`。
- 名字只能用字母、数字、下划线、连字符。
- 服务器**按需启动**：模型真正要用它时才会拉起连接；没开的后端只会显示连不上，不拖慢平时使用。
- 工具在模型侧显示为 `mcp__<服务器名>__<工具名>`。

### 本机三件套的实测配方（照抄可用）

| 工具 | 传输 | 配置 | 前提 |
|---|---|---|---|
| **IDA Pro** | streamable HTTP | `"url": "http://127.0.0.1:13391/mcp"` | IDA 里装了 MCP 插件（`%APPDATA%\Hex-Rays\IDA Pro\plugins`），打开数据库后插件自动起服务（默认 `127.0.0.1:13391`，路由 `/mcp`）。实测 66 工具 + 7 资源 |
| **jadx** | stdio | `python jadx_mcp_server.py --jadx-host 127.0.0.1 --jadx-port 8650` | jadx-gui 打开目标；插件 jar 放在 `~/.jadx/plugins/`。实测 32 工具 |
| **Burp Suite** | stdio（走官方代理） | `java -jar mcp-proxy-all.jar --sse-url http://127.0.0.1:9876` | Burp 已加载官方 MCP 扩展（Extensions → Add → Java → `burp-mcp-all.jar`），扩展页签 Enabled。实测 27 工具 |

Burp 的坑（都踩过）：
- 端点在**根路径** `http://127.0.0.1:9876`，不是 `/sse`；裸 GET 一律 403，要用真正的 MCP 客户端（POST + initialize）。
- 扩展页签里的 **Require approval for HTTP requests** 打开时，模型第一次发请求可能需要在 Burp 里点确认；想免打扰就把它关掉，或在 **Auto-Approved HTTP Targets** 里填目标域名。

### MCP 排错表

| 症状 | 原因 | 改法 |
|---|---|---|
| 工具列表里没有 `mcp` | 适配器扩展没加载 | 新建会话；检查设置里"加载资源"是否为开 |
| 连不上 | 后端进程没起 | IDA 打开数据库 / jadx-gui 打开文件 / Burp 启动并启用扩展 |
| 403 | 走了 SSE 的裸 GET 或 URL 写错 | 用 stdio 代理或正确的 `/mcp` 地址 |
| 端口占用 | 已有实例在跑 | 关掉旧实例，或改端口并同步改配置 |

## 5. 权限：四层交集

**全局 → 角色 → 会话 → 临时授权**，逐层求交；每层可给"允许 / 询问 / 拒绝"。

- **临时授权**有面额（15 分钟 / 30 / 60 / 120 / 240 分钟），到期自动失效。
- `权限` 页能看到**最终生效的权限**以及它是怎么算出来的（哪一层给的结果）。
- 询问型权限在对话里表现为一次确认（扩展 UI 请求）。

注意：权限是**工具级**的。想要"bash 只允许跑这几条命令""读写限制在工作区内"这种参数级策略，当前版本还不支持（见 01 文档的"已知边界"）。

## 6. 子智能体委派

角色 JSON 里的一段配置：

```jsonc
"delegation": {
  "enabled": true,
  "mode": "background",          // 后台并行（父不等）
  "requireAudit": true,          // 硬闸门：父必须先自己动过手（≥1 次工具调用）才允许派人
  "deliverOn": "turn_end",       // 结论在父回合结束后合并成一条消息；"checkpoint" = 提前插话
  "allowedRoles": ["ctf-recon", "ctf-verify", "ctf-route"],
  "maxChildren": 3,              // 按父会话生命周期累计，防止无限扩张
  "maxParallel": 2,
  "maxDurationSeconds": 600,
  "stopOnFlag": true,            // 主 Agent 给出候选 flag → 停掉还在跑的子智能体
  "inherit": { "model": "own" }  // 子智能体用自己的模型（也可继承父的）
}
```

配套：子角色（如 `ctf-recon`）就是普通角色，只是提示词与工具更窄（例如只给 `read/grep/ls/find/web_search`，禁 `write/shell`）。

**自动收口的四种情况**（防止"父已收工、子还在烧 token"）：
1. 父会话停止（切工作区 / 关闭窗口）；
2. 用户按「停止」（中止当前回合）；
3. 结果**无人接收**（父进程已退出）；
4. 主 Agent 给出候选 flag（`stopOnFlag`）。

模型自己也可以在不需要时调 `delegation_stop` 停掉子智能体；提示词里明确要求"解出来就停掉它们"。

## 7. 会话、工作区与记忆

- **会话**：左栏按工作区分组；新建 / 切换 / 重命名 / 删除。会话文件在 `<数据目录>/sessions/`。
- **工作区**：就是 Pi 的工作目录。切换工作区 = 换一套会话列表 + 换 `cwd`。
- **记忆**：应用记住"上次用哪个工作区、哪个会话、哪个角色"，重启后恢复；每个会话记得自己属于哪个角色。
- **新建会话后要重新取一次用量**（上下文环归零），这是已修的行为；如果你看到环上还挂着上一个会话的数字，请反馈。

⚠️ 三条"改了不生效"的经典原因：
1. **工具/扩展/技能改动** → 要**新建会话**（启动参数决定）；
2. **密钥改动** → 要**新建会话**；
3. **工作区切换** → 界面上看的是新工作区，但**正在跑的回合不会迁移**（先停止再切）。

## 8. 常见配置错误速查

| 症状 | 原因 | 改法 |
|---|---|---|
| 模型说"没有 bash 工具" | 角色工具白名单里没给它 | 角色页 → Pi 工具 → 勾上 bash（或"不限制"） |
| 工具清单和实际不符 | 清单是检测结果，不是保证 | 让模型先 `command -v` 确认；或修好 shell（见下条） |
| bash 里的命令找不到（`python: command not found`） | bash 落到了 WSL，而工具装在了 Windows | 本版本已在启动时把配置的 shell 目录前置到 PATH；若仍不对，检查设置里的 shell 路径 |
| 子智能体结果迟迟不回来 | 后端/父会话状态 | 看标签页状态；父空闲时结论会直接唤醒它，父在跑时排队等回合结束 |
| 子智能体一直在跑 | 任务太大 | 标签页上有 ✕ 可停；或调小 `maxDurationSeconds` |
| 上下文环数字不变 | 极少数情况下统计没刷新 | 切一次会话或等回合结束（会自动重取） |

## 工具清单（tool-catalog.json）：本机工具不再写死

界面「工具」页有三块，来源完全不同：

| 区块 | 来源 | 要不要配 |
|---|---|---|
| **模型可调用的工具**（内置/扩展/MCP） | **自动加载**：解析会话 system 消息里的工具清单 | 不用配，装了就出现 |
| **MCP 服务器** | `mcp.json`（+ 适配器写的 `mcp-cache.json`） | 界面里增删 |
| **本机环境工具**（命令/包/桌面程序） | **`tool-catalog.json`** | 想加就改这份 JSON |

### 文件位置（优先级：项目 > 用户 > 内置默认）

```
<工作区>/.pi/tool-catalog.json     项目级：跟项目走，可进 git，团队共享
<数据目录>/tool-catalog.json        用户级：这台机器上通用
（内置默认清单编译在程序里，没文件时用它）
```

### 怎么改

1. 工具页 →「导出清单」→ 生成带注释的 JSON（已存在就存成 `tool-catalog.export.json`，不会覆盖你的）；
2. 改完保存（**可以留 `//` 注释**，读的时候会剥掉）；
3. 工具页 →「重新加载」→ 立即生效，**不用重启**。

### 字段

```jsonc
{
  "version": 1,
  "mode": "",                      // "replace" = 整份替换内置默认（企业定制）
  "directions": [                  // 分组与中文名
    { "id": "reverse", "label": "逆向", "hints": ["file", "strings", "objdump"] }
  ],
  "tools": [
    { "id": "jq", "name": "jq", "type": "command", "direction": "base",
      "capabilities": ["data.json"],            // 能力标签：角色声明能力就靠它映射
      "detect": { "commands": ["jq"] },         // 怎么发现它（见下表）
      "versionArgs": ["--version"],             // 取版本用什么参数（ExifTool 要 -ver）
      "note": "命令行 JSON 处理" },

    { "id": "pycryptodome", "type": "python-package",
      "detect": { "pythonImport": "Crypto" } },

    { "id": "ghidra", "type": "application",
      "detect": { "paths": ["%USERPROFILE%\\ghidra*\\ghidraRun.bat"] } }
  ],
  "capabilities": [ { "id": "my.thing", "label": "我的能力" } ],   // 只声明、暂无人实现也行
  "capabilityRules": [ { "match": "web_*", "capabilities": ["web.search"] } ]  // 给自动发现的工具挂能力
}
```

`detect` 四种探测手段：`commands`（PATH 里找可执行）、`paths`（安装路径，支持 `%VAR%` 与 `*`）、
`pythonImport`（试 `import`）、`nodeModule`（试 `require.resolve`）。
`type` 取值：`command` / `python-package` / `node-package` / `application`。

### 合并规则（4 条）

| 写法 | 效果 |
|---|---|
| 同 `id` | 字段级覆盖（只写要改的字段，其余继承内置） |
| 新 `id` | 追加 |
| `"disabled": true` | 删掉内置的那一条 |
| `"mode": "replace"` | 整份替换内置默认 |

清单有问题不会静默失效：解析失败会**回退内置默认**，并在工具页「工具清单来源」里报出文件与原因。

### 扩展包（Pi 包）是怎么加载的

**装了就会自动加载**——Pi 官方机制（`docs/packages.md`）：

```bash
pi install npm:@example/pi-tools@1.0.0     # 也可以 git:github.com/xxx@v1 或本地路径
pi list                                     # 看装了哪些
pi remove <source>                          # 卸载
pi update --extensions                      # 升级后重新对齐
```

个人级写入 `~/.pi/agent/settings.json`（便携模式下就是 `<exe目录>/.pi/settings.json`），
`--local` 写到项目级；项目级包要**先信任项目**才会加载（包能执行扩展代码，这是有意的安全设计）。

**一个目录/包算不算 Pi 包**，按官方发现规则判断（ZeroA 的界面用同一套规则）：

| 规则 | 说明 |
|---|---|
| `package.json` 里有 `pi` manifest | 显式声明 `extensions` / `skills` / `prompts` / `themes` |
| **或者**有约定目录 | 存在 `extensions/`、`skills/`、`prompts/`、`themes/` 之一（无需 manifest） |
| **或者** `keywords` 含 `pi-package` | gallery 收录标记 |

ZeroA 的「工具 → 模型可调用的工具」里，包清单**优先用 `pi list`**（权威：认所有安装方式与作用域），
`pi list` 不可用时退回扫 `<数据目录>/npm/node_modules`。工具清单本身来自会话——
因为"包在"不等于"工具真的注册上了"（版本不兼容、设置里关掉扩展、`--tools` 白名单都会影响）。

### 让 AI 帮你维护清单（环境管理员角色）

清单是**可写的**：检测到的真实路径会写回 JSON，模型也能登记它找到或刚装好的工具。

**专门的角色**：`环境管理员`（id `toolkeeper`）——内置角色，装上就有。它做的事：

```
① catalog_list   看账本（清单里已登记了什么）
② catalog_check  实测一遍（可用/不可用、真实路径、版本），并把新路径写回清单
③ 缺什么补什么    装好之后用 catalog_add 登记（绝对路径 / 命令名 / 能力标签）
④ catalog_check  再验一次，确认显示 ✓
⑤ 报告           原有可用数 → 现在可用数，新增或修正了哪些，还缺什么
```

它给模型的四个工具（由工作台生成的扩展 `extensions/tool-catalog.ts` 提供）：

| 工具 | 作用 |
|---|---|
| `catalog_list` | 查看清单（id / 类型 / 方向 / 能力 / 记录路径） |
| `catalog_check` | 跑真实检测；默认**把新发现的路径写回清单** |
| `catalog_add` | 登记或更新一条（至少给一条线索：`path` / `commands` / `pythonImport` / `nodeModule`） |
| `catalog_record` | 把自己实测到的绝对路径记进清单 |

为什么需要它：做题时会现装新库或新工具（`pip install pycryptodome`、下载 ffuf），
不登记的话下次启动又变成"本机没找到"；而 PATH 外的工具（工具箱自带目录、便携包、pip 的 Scripts）
只有记绝对路径才找得回来。

**三条写入路径的区别**：

| 谁写 | 写到哪 | 何时 |
|---|---|---|
| 程序（检测结果） | `<数据目录>/tool-catalog.json`，`addedBy: "detect"` | 点「工具 → 重新检测」，或模型调 `catalog_check` |
| 模型（登记新工具） | 同上，`addedBy: "ai"` | 模型调 `catalog_add` / `catalog_record` |
| 人（手写） | 项目级 `<工作区>/.pi/tool-catalog.json`（**程序不会自动改写**） | 随时 |

> 用户级清单会被程序重写（手写注释会丢），文件头已写明这件事；
> 想长期维护自己的注释与分组，就写进项目级清单。

#### 「模型可调用的工具」这份清单从哪来

来自 **Pi 扩展在会话启动时上报的真实工具集**（文件 `<数据目录>/pi-tools.json`）：

- 扩展在 `session_start` 时调用 Pi 的 `getActiveTools()` / `getAllTools()`，把**真正声明给模型的工具**
  写进这个文件（含内置/扩展/MCP，以及哪些是"已注册但本次未启用"）。
- 应用优先读它；没有这个文件时退回解析会话系统提示里的工具段落。

> 为什么不能直接解析会话提示：那段 "Available tools" 只是**精选片段**——
> 实测连默认启用的 `read`/`edit`/`write` 都不在里面。按它显示会又缺又错。
