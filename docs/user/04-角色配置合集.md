# ZeroA · 角色配置合集（可导入）

这篇把**可直接带入的角色**整理成一份说明：每个角色干什么、给了哪些工具与权限、它们之间怎么配合。
配套的可导入文件在分发包的 `roles-pack/` 目录里（`*.json` + `prompts/*.md`）。

> 导入方法见文末《一次性导入》。改完角色**要新建会话**才生效（提示词与工具集在启动时确定）。
>
> 能力（`capabilities`）是**授权语义**：角色页「能力」页签里勾选了的才会给这个角色——
> 提示词里的环境清单只包含勾选能力在本机解析到的工具，没勾选的一律不给。
> 没声明能力的角色（如默认的 `zeroa`）不带本机工具清单，只用 Pi 自带的能力。
> 本机完整工具清单看「工具」页，它与角色解耦。

---

## 1. 角色地图

```
        ┌──────────────────────────── ZeroA（默认角色 / 通用起点）────────────────────────────┐
        │  不预设方向，用来做"一个人 + 一套工具"的日常任务                                    │
        └────────────────────────────────────────────────────────────────────────────────────┘

  CTF 竞赛（ctf）  ← 父 Agent：主路线、判断、最终交付
    ├── CTF 资料检索（ctf-recon）   只读 + 联网：查 writeup / 文档 / 工具用法
    ├── CTF 结论复核（ctf-verify）  只读 + bash：专门找反例，复核候选 flag
    └── CTF 路线探索（ctf-route）   只读 + bash：并行试不同解法路线

  应急响应（ir）      固定证据 → 时间线 → 结论与处置建议
  数字取证（forensics）镜像 / 日志 / 内存：提取、关联、出可复核报告
  通用编码（general）  日常开发：最小改动、可回滚
```

三个子角色的存在意义是**上下文隔离**：它们各自开独立进程、独立会话，
父 Agent 不用把它们的全部过程塞进自己的上下文——只收结论摘要，然后自己复核。

## 2. 父角色：CTF 竞赛（`ctf`）

| 项 | 值 |
|---|---|
| 定位 | Web / Pwn / Crypto / Reverse 解题：侦察 → 假设 → 最小复现 → 利用 → 交付 |
| 思考级别 | `high` |
| 工具 | **不限制**（read / bash / edit / write…）——它要能写 exp、跑脚本 |
| 会话名前缀 | `[CTF]`（新会话按首条消息命名时会带上） |
| 委派 | 打开，`mode: background`，`deliverOn: turn_end`，`requireAudit: true`，`stopOnFlag: true` |
| 预算 | 最多 3 个子智能体、同时 2 个、单个最长 600 秒 |
| 允许派 | `ctf-recon` / `ctf-verify` / `ctf-route` |

关键设计点（也是这份配置值得抄的地方）：

- **`requireAudit: true`**：父 Agent 必须先自己动过手（至少一次工具调用）才允许派人。
  这条挡的是"一上来就把活全推出去"——它自己都没看题，派出去的任务描述必然是空的。
- **`deliverOn: turn_end`**：子智能体的结论在父**这一轮结束后**合并成一条消息交给它，
  不打断正在进行的回合。父空闲时结论会直接唤醒它开新的一轮。
- **`stopOnFlag: true`**：父给出候选 flag 就停掉还在跑的子智能体——已经拿到答案了，
  再让它们跑只是烧 token。
- **`inherit.model: own`**：子智能体用自己的模型（可以在子角色里单独配更便宜的模型）。

角色的提示词（`prompts/ctf.md`）只写了工作流与纪律，**没有写"什么时候派人"**——
那段是程序按你的委派配置自动生成的（见 `roles/prompts/ctf.delegation.md`），
所以改了 `allowedRoles` / `maxChildren`，模型看到的说明会跟着变，不会写歪。

## 3. 子角色

> 三个子角色都是**子智能体**（定义里 `"kind": "agent"`）：它们只能被别的角色委派，
> 不会出现在输入框的角色选择器里，也不能再派自己的子智能体。
> 角色管理页把它们单独分区展示；要把一个普通角色变成子智能体，在左栏右键它选「复制为子智能体」。
> 委派白名单只能填子智能体的 id——填了已存在的普通角色会在保存时直接报错。

### CTF 资料检索（`ctf-recon`）—— 查资料的

| 项 | 值 |
|---|---|
| 工具 | `read` `grep` `ls` `find` `web_search` `fetch_content` |
| 权限 | `filesystem.write: deny`、`shell.execute: deny` |
| 能力 | `web.search`、`web.fetch` |
| 思考级别 | `medium` |
| 提示词要点 | 只做检索与摘录；给出来源；**区分"文档说的"和"我实测的"**；不做利用 |

为什么禁写禁 shell：检索型角色的价值在于"不出手"，它一旦能改文件/跑命令，
就越界成了第二个执行者，父 Agent 还得去核对它到底动了什么。

### CTF 结论复核（`ctf-verify`）—— 专门找反例的

| 项 | 值 |
|---|---|
| 工具 | `read` `grep` `ls` `bash` |
| 权限 | `filesystem.write: deny`、`network.public: deny` |
| 提示词要点 | 目标是**驳倒**结论而不是复述；给出反例或"我复现失败"；明确说清哪一步没验证 |

它保留了 `bash`（要能真跑一遍验证），但禁写、禁外网——复核只需要看和跑。

### CTF 路线探索（`ctf-route`）—— 并行试路线的

| 项 | 值 |
|---|---|
| 工具 | `read` `grep` `ls` `bash` |
| 权限 | `filesystem.write: deny` |
| 提示词要点 | 每条路线给"假设 + 需要的证据 + 置信度"；不做最终判断 |

## 4. 其他角色

| 角色 | id | 定位 | 工具 | 思考级别 |
|---|---|---|---|---|
| ZeroA | `zeroa` | 多智能体安全工作台（默认起点，不预设方向） | 不限制 | 默认 |
| 应急响应 | `ir` | 入侵排查：先固定证据 → 再看时间线 → 最后给结论与处置建议 | 不限制 | `high` |
| 数字取证 | `forensics` | 镜像 / 日志 / 内存取证：提取、关联、形成可复核报告 | 不限制 | 默认 |
| 通用编码 | `general` | 日常开发：读代码、改功能、跑测试，改动最小且可回滚 | 不限制 | 默认 |

> 现在**只有 `zeroa` 是内置角色**（界面上不可删除，可编辑或复制）。
> `ir` / `forensics` / `general` / `ctf` / `toolkeeper` 与三个子智能体都在 `roles-pack/` 里，按需导入；
> 导入进来的是普通角色，可删可改。（老版本补种过的内置角色升级后自动转为普通角色，内容不动。）

## 5. 委派字段一览（`delegation` 段）

界面上在 `角色` 页的「子智能体」页签里配；手写 JSON 时字段如下。
这段是**带外策略**：不放进工具参数，模型自己改不了；实际上限还要与会话授权取交集。

| 字段 | 取值 | 含义 |
|---|---|---|
| `enabled` | true / false | 不写或 false = 这个角色完全不能派子智能体（安全默认） |
| `allowedRoles` | 子智能体 id 列表 | 白名单，只能填**子智能体**（`"kind": "agent"` 的定义）。**空列表 = 一个都不能派**（不是"不限制"） |
| `mode` | `background`（默认）/ `blocking` | ⚠️ `blocking` 暂未实现：写了只在保存时给警告，实际仍是受理后立即返回 |
| `deliverOn` | `turn_end`（默认）/ `checkpoint` | `turn_end` = 回合结束后合并投递；`checkpoint` = 子智能体一完成立刻插话（父正忙时走 steer） |
| `requireAudit` | true / false | true = 父会话至少调过一次工具才允许派人 |
| `stopOnFlag` | true / false | 父给出候选 flag 就停掉还在跑的子智能体；不写视为 true |
| `maxChildren` / `maxParallel` | 数字 | 按这条会话计的累计 / 同时在跑预算，0 = 用默认值 |
| `maxDurationSeconds` | 数字 | 单个子智能体的时限（秒），0 = 不限时 |
| `idleTimeoutSeconds` | 数字 | 可继续子智能体空闲多久后自动回收（秒），0 = 默认 10 分钟 |
| `lifecycle` | `continuable`（默认）/ `one-shot` | `continuable` 跑完保留进程、可继续发消息；`one-shot` 跑完即释放，省内存 |
| `inherit` | 对象 | ⚠️ 暂未实现：子智能体按**子角色自己的定义**启动（模型缺省沿用父模型），写了只在保存时给警告 |

保存时的校验：枚举写错（`mode` / `deliverOn` / `lifecycle` 以外的值）、白名单里的 id
不合法、白名单引用了**已存在的普通角色**（不是子智能体）、预算写成负数，都会在保存时直接被拒
——不会留到启动时才炸。白名单引用的 id 还不存在则放行（先配父角色、后建子智能体是正常顺序），
派发时还有一道闸门兜底。

## 6. 一次性导入

### 方式 A：拷文件（最快）

```
把 roles-pack/*.json           →  <ZeroA目录>\.pi\roles\
把 roles-pack/prompts/*.md      →  <ZeroA目录>\.pi\roles\prompts\
然后重启应用（角色列表在启动时扫描）
```

### 方式 C：界面导入（最省事）

`设置 → 角色 → 角色导入 / 导出` → 在「导入」里填**文件或目录路径** → 导入。
两种都认：

- 本项目导出的**自包含 JSON**（`*.json`，含提示词正文）；
- **目录**形式（`roles-pack/` 那种：`*.json` + `prompts/<id>.md`）。

导入结束后界面会列出「新增 / 覆盖 / 失败」以及失败原因；同名角色**直接覆盖**，改完要新建会话才生效。
反向操作同理：在上面那块「导出」里勾选角色、留空路径即存到 `.pi/exports/roles-<时间>.json`。

### 方式 B：界面新建（适合再改）

`角色` 页 → 新建角色 → 按上面表格填：身份（id / 名称 / 图标 / 会话名前缀）、
思考级别、工具勾选、权限、委派（「子智能体」页签，字段见第 5 节）；提示词粘进「角色提示词」框 → 保存。

### 导入后自检

1. `角色` 页应出现这些角色；`ctf` 的「子智能体」页签里能看到三个允许的子角色；
2. 选 `ctf` 角色**新建会话**，让它"把你当前可用的工具名逐个列出来"——
   应包含 `delegate_task`、`delegation_stop`、`delegation_list`；
3. 再来一句："先读一下工作区里的 X，再用 delegate_task 派 ctf-recon 去查 Y，你自己继续"——
   顶部会出现子智能体标签页，父这一轮会很快结束（它不等），结论稍后自动回到会话里。

> ⚠️ 三个子角色必须先存在、而且是子智能体（`"kind": "agent"`）：`ctf` 的 `allowedRoles`
> 指向 `ctf-recon` / `ctf-verify` / `ctf-route`。只导入 `ctf.json` 而漏了子角色的 JSON，
> 派活会被 Go 侧闸门拒绝（"子智能体不存在"）；把整包一起导入即可（目录导入是整体读入的）。
> 自己手写子角色时别忘了 `"kind": "agent"`——写成普通角色的话，保存 `ctf` 时就会被拦。
